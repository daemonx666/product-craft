## Skills

| Skill | 内容 |
|---|---|
| [spec](skills/spec/SKILL.md) | 一行の機能アイデアを、現在のプロジェクトに基づいた AI が読みやすい完全な仕様書に展開し、その仕様に沿って実装します |

## spec

AI によるコーディングで最も無駄が出るのは、要件の推測を誤ったときです。`spec` はコードを書く前に少数の的確な質問で重要な判断を固め、その結果をファイルに保存します。後のセッションや別の agent も、そのファイルから作業を再開できます。

**ワークフロー**

1. **プロジェクトを読む**：README、CLAUDE.md / AGENTS.md、依存関係の定義、既存の仕様、アイデアに関連するコードを読みます。関連機能については、データの保存方法、処理の流れ、使われている UI コンポーネントを把握します。
2. **類似プロダクトを探す**：同じ分野でこの機能を持つプロダクトやオープンソースプロジェクトを 2〜4 個挙げ、どう実装しているか、何を取り入れるか、何が合わないかをまとめます。
3. **質問は一度に一つ**：各質問に 2〜4 個の選択肢を出し、先頭を推奨案にします。コードから分かることは聞きません。通常 3〜8 問で、「おすすめで」と言えば残りを省略できます。
4. **仕様書を書く**：`docs/specs/<日付>-<名前>.md` に、現状、類似プロダクト、目標と非目標、Given/When/Then 形式の受け入れ基準付きの番号付き要件、再利用 / 変更 / 追加に分けた技術方針をまとめます。
5. **確認**：コードを書く前に必ず確認します。
6. **実装**：タスクを一つずつ進めて仕様書のチェックを付け、最後にすべての受け入れ基準を確認します。

**設計方針**：新機能はプロジェクトに既にあるものの上に積み上げます。既存モジュールを拡張し、既存のデータ構造、コンポーネント、慣習を再利用します。別系統を新設したり既存の挙動を変えたりする場合は、仕様書に理由を書き、先に確認します。

**使い方**

| ツール | 呼び出し方 |
|---|---|
| Claude Code | `/spec フレンドランキングを追加` |
| Codex | `$spec フレンドランキングを追加` |

「ランキングを作りたいので、まず要件を整理して」のようにアイデアを伝えるだけでも自動で起動します。途中の仕様を再開するには「continue spec」または「spec の続き」と伝えてください。

仕様書は会話で使っている言語で書かれます。

## インストール

```bash
git clone https://github.com/felix-xqs/product-craft.git
cd product-craft
./install.sh
```

`install.sh` は `skills/` 以下の各フォルダへのシンボリックリンクを次の場所に作成します。

- `~/.claude/skills/`：Claude Code
- `~/.agents/skills/`：Codex

シンボリックリンクなので、`git pull` するだけで skill が最新になります。skill を追加したらスクリプトをもう一度実行してください。

## リポジトリ構成

```
product-craft/
├── install.sh
└── skills/
    └── spec/
        ├── SKILL.md
        └── references/spec-template.md
```

skill を追加するには、`skills/<name>/SKILL.md` を作成し、frontmatter に `name` と `description` を書きます。長い参考資料は `references/` に置き、いつ読むべきかを SKILL.md に書いてください。
